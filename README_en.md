# frp Enterprise

[中文](README.md) | English

**frp Enterprise** is a heavily customized edition of [frp](https://github.com/fatedier/frp) for small and medium businesses that want to run reverse proxying **on their own servers**:

- **Client**: employees sign in from a desktop client, and administrators see every device's login state and decide who may connect.
- **Server**: the dashboard signs in through the company's existing OIDC single sign-on (for example Synology SSO), and every action is audited.
- **Deployment**: the whole stack starts with one Docker command.

All of frp's forwarding features (TCP / UDP / HTTP / HTTPS / STCP / XTCP …) are kept. On top of them it adds what company networks lack: device identity, approval, visibility and auditing.

## Features

- **Per-device auth codes.**
  - Each device logs in with an auth code, bound to that device on first use.
  - Codes are either issued by an administrator, or generated by the client and **approved or rejected** in the dashboard.
  - Revoking a code disconnects its device at once.
- **Visible login state.** Clients show *connecting / waiting for approval / running / rejected*. The dashboard shows each code's host, IP, last-seen time and whether it is online.
- **Desktop client HDIT-FRPE-Client for Windows, macOS and Linux.** It is built with [MyGo](https://mygo.egoist.dev) native UI and embeds frpc in one executable. It shows:
  - The connection state, the public IP and the local IPs.
  - This device's port mappings.
  - Ports already taken by other clients; a taken remote port cannot be chosen.
  - Server notices and logs.

  Settings are encrypted with a machine-bound key. An optional lock shows only the status and a restart button until the password is entered.
- **Dashboard accounts.**
  - **One local account:** at the first login after deployment it sets up TOTP and receives one-time recovery keys.
  - **Everyone else uses OIDC**, matched by user name. Unknown users must be **approved by another administrator**.
  - There are no roles: every administrator has the same rights.
- **Audit log and runtime log** in the dashboard.
- **Look and branding.** The dashboard and the client use a Pulse-style layout: a sidebar with colored icons, metric cards and dot-matrix sparklines. The settings page sets the site name, the logo, light or dark theme, the accent color and the top right link. Connected desktop clients follow the name, logo and accent at once.
- **Notices** sent from the dashboard to all clients or to one device.
- **Docker deployment.**
  - The image runs as a non-root user and keeps its data in `/data`.
  - A compose file is included.
  - GitHub Actions builds `linux/amd64` and `linux/arm64` images and pushes them to GHCR.

## Quick start

```bash
git clone https://github.com/czwstc/frp-enterprise.git
cd frp-enterprise/deploy/docker
cp .env.example .env   # token, local admin password, OIDC settings
docker compose up -d
```

1. Open `http://<server>:7500` and sign in with the local account.
2. Scan the QR code with an authenticator app and save the recovery keys.
3. Generate an auth code on the **鉴权码** page and give it to an employee.
4. The employee enters the server address, token and auth code in the desktop client.

   A command-line frpc uses this config instead:

   ```toml
   serverAddr = "frp.example.com"
   serverPort = 7000
   auth.token = "same token as the server"
   clientID = "office-pc-01"
   loginFailExit = false
   enterprise.authCode = "XXXX-XXXX-XXXX-XXXX"
   ```

The Chinese [README](README.md#docker-部署指南) has the full Docker deployment guide: preparation, writing `docker-compose.yml` by hand with host directories mounted for the config (`/etc/frp/frps.toml`, read-only) and data (`/data`, writable by UID 1000), `.env`, pulling from GHCR, HTTPS reverse proxy (Caddy and Nginx), changing the port range, upgrades, backups and troubleshooting. See also [deploy/docker/README.md](deploy/docker/README.md) and [conf/frps_full_example.toml](conf/frps_full_example.toml) for every option.

## Desktop client downloads

Get HDIT-FRPE-Client for macOS (universal `.dmg`), Windows x64 (`.zip`) and Linux x64/ARM64 (`.deb`, `.tar.gz`) from [Releases](https://github.com/czwstc/frp-enterprise/releases). The builds are not code-signed yet: on macOS open the app with right-click → Open the first time.

## Building

```bash
make web && make build    # bin/frps, bin/frpc
make test                 # unit tests
make gui                  # desktop client for this platform (Go >= 1.27.3)
make gui-cross            # desktop client for macOS, Windows and Linux
```
